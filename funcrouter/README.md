# FuncRouter

**Routing. Just JavaScript.**

Независимый ESM-пакет без runtime-зависимостей. Принимает маршруты, guards и
обычные функции. Обработчик может рисовать DOM, вызывать FuncUI, VanJS или Lit,
обновлять Web Component или рисовать на canvas. Библиотека не импортирует FuncUI
и не создаёт DOM. Перехват HTML-ссылок включается отдельно.

```js
import { createRouter, route } from 'funcrouter';

const router = createRouter([
  route('/', home),
  route('/login', login),
  route('/users', {
    beforeEnter: [requireUser],
    children: [
      route('', users),
      route(':id', { params: { id: parseId } }, user)
    ]
  }),
  route('/files/*path', files),
  route('*', notFound)
]);

await router.start({ links: document });

function user({ params, query, signal }) {
  console.log(params.id, query.get('tab'));
  // Любая отрисовка. Для фоновой работы используйте signal.
  // return () => { ...освободить ресурсы страницы... };
}

function parseId(value) {
  const id = Number(value);
  if (!/^\d+$/.test(value) || !Number.isSafeInteger(id) || id < 1) {
    throw new TypeError('ID должен быть положительным целым числом.');
  }
  return id;
}

function requireUser({ to }) {
  return session.user ? true : `/login?next=${encodeURIComponent(to.url)}`;
}
```

`home`, `login`, `users`, `files`, `notFound` и `session` в примере предоставляет
приложение. Это не специальные компоненты или объекты роутера.

## Маршруты

```js
route('/about', handler);
route('/users/:id', { params: { id: parseId } }, handler);
route('/users', { children: [route('', list), route(':id', profile)] });
```

Второй аргумент — обработчик либо объект настроек. С настройками обработчик
передаётся третьим аргументом. Группа с `children` может обходиться без обработчика.
Если обработчик есть и у родителя, он соответствует точному пути родителя;
дочерние страницы вызывают собственный конечный обработчик.

| Путь | Что означает |
| --- | --- |
| `/users/new` | Статический путь |
| `/users/:id` | Один обязательный сегмент |
| `/help/:topic?` | Один необязательный сегмент |
| `/files/*path` | Остаток пути, включая пустой |
| `*` | Общий fallback; остаток доступен как `params.path` |
| `''` у ребёнка | Точный путь родителя, индексная страница |

Дочерние пути относительные, без начального `/`. Параметры и guards родителей
наследуются. `*name` и `*` допустимы только в конце полного пути.

Роутер сопоставляет полный путь и учитывает регистр. В каждом сегменте порядок
приоритета: точное окончание пути → статический сегмент → обязательный параметр →
необязательный → wildcard. При одинаковом приоритете сохраняется порядок объявления.
Одинаковые шаблоны, в том числе `/:id` и `/:name`, отклоняются при создании роутера.
Завершающий `/` не влияет на выбор маршрута. Двойные `/` внутри пути не сжимаются.

Параметры декодируются по сегментам: `%2F` остаётся частью одного параметра.
По умолчанию значения строковые. `params` в настройках — синхронные функции
преобразования. Для отсутствующего необязательного параметра parser не вызывается.
Исключение parser, `undefined`, `NaN`, бесконечность или Promise означают ошибку
параметра; роутер не подменяет её попаданием в wildcard.

## Данные маршрута

Обработчик получает `{ url, path, params, query, hash, route, matched, from, signal }`.

- `url` — адрес внутри приложения с query и hash, например `/users/2?tab=bio#name`.
- `path` — pathname без завершающего `/`, кроме корневого `/`.
- `params` — разобранные параметры. Объект доступен только для чтения.
- `query` — стандартный `URLSearchParams`: `get()`, `getAll()`, `has()`.
- `hash` — фрагмент с `#` или пустая строка. В hash-режиме это фрагмент внутри маршрута.
- `route` — конечная запись, `matched` — цепочка от родителя до неё.
- `from` — предыдущий принятый маршрут или `null` при запуске.
- `signal` — отмена времени жизни страницы после принятого ухода или `stop()`.

`current`, `resolve()` и подписки предоставляют данные маршрута без `from` и
`signal`. Объект маршрута и `params` заморожены. `query` — отдельный обычный
`URLSearchParams`; его изменение не выполняет навигацию.

## Guards

`beforeEnter` и `beforeLeave` можно задавать на маршруте и в настройках
`createRouter(routes, options)`. Значение — функция или массив функций.

```js
route('/editor', {
  beforeEnter: [async ({ to, from, signal }) => {
    const response = await fetch('/api/session', { signal });
    return response.ok ? true : '/login';
  }],
  beforeLeave: [() => !dirty || confirm('Уйти без сохранения?')]
}, editor);
```

Возвращаемые значения:

| Результат | Поведение |
| --- | --- |
| `true` или `undefined` | Продолжить |
| `false` | Отменить переход |
| Строка или `URL` того же origin | Перенаправить и проверить новую цель |
| Исключение / отклонённый Promise | Отменить переход и сообщить об ошибке |

Порядок: глобальные `beforeLeave` → выходные guards от ребёнка к родителям →
глобальные `beforeEnter` → входные guards от родителей к ребёнку → обработчик.
Проверки выполняются последовательно. Они запускаются также при изменении
параметров, query и hash. Повторный переход на тот же полный URL — пустая операция.

При перенаправлении выходные guards повторно не выполняются, входные проверки
новой цели выполняются полностью. Перенаправления используют `replace`, поэтому
не создают недоступные промежуточные записи. Повтор URL или цепочка из 16
перенаправлений считается циклом.

Новый переход отменяет предыдущую ожидающую проверку. Даже если Promise guard
никогда не завершится, старая навигация вернёт `false`; её обработчик не запустится.
Для отмены собственных запросов guard использует свой `signal`.
Текущая страница при ожидании или отказе остаётся активной; её `signal` ещё не отменён.

## Управление

```js
await router.start();                          // обработать текущий адрес
await router.start({ links: document });       // ещё и перехватывать HTML-ссылки
await router.navigate('/users/42');            // новая запись истории
await router.navigate('/login', { replace: true });

const current = router.current;               // null до первого перехода и после stop
const match = router.resolve('/users/42');     // поиск без навигации, null если не найден
const unsubscribe = router.subscribe(current => console.log(current.url));
unsubscribe();
router.stop();
```

`start()` и `navigate()` возвращают `Promise<boolean>`: `true` — цель принята,
`false` — отмена, вытеснение новым переходом или отсутствие подходящего маршрута.
Ошибки отклоняют Promise. Повторный `start()` уже работающего роутера возвращает
`false`. Перед `navigate()` нужен `start()`.
Ошибка начального маршрута отклоняет `start()`, но роутер продолжает слушать
историю и ссылки: приложение может показать ошибку и перейти на корректный адрес.

`resolve()` синхронный: выполняет сопоставление и parsers, не вызывает guards,
обработчик или подписки и не изменяет историю. Ошибки parser передаются вызывающему коду.

Подписки вызываются после успешной отрисовки и не вызываются при регистрации.
Возвращённая функция удаляет подписку; подписки сохраняются между `stop()` и
повторным `start()`. Ошибка одной подписки не мешает остальным.

Ссылки перехватываются при обычном левом клике. Ctrl/Cmd/Shift/Alt, другой target,
`download`, `rel="external"`, внешний origin, пути вне `base` и локальные якоря
сохраняют браузерное поведение. Можно передать контейнер вместо `document`.
Без опции `links` роутер не подключает обработчики DOM.

`stop()` безопасно вызывать повторно. Он снимает listeners истории и ссылок,
отменяет ожидающие guards и время жизни текущей страницы, вызывает её cleanup.
Guards выхода при остановке не запускаются. Повторный `start()` заново обрабатывает
текущий адрес.

## История и окружение

```js
createRouter(routes);                             // mode: 'history'
createRouter(routes, { base: '/app/' });           // browser URL /app/users/42
createRouter(routes, { mode: 'hash' });            // browser URL /#/users/42
createRouter(routes, { mode: 'memory', initial: '/users/42' });
```

`history` использует History API и требует серверный fallback на `index.html`
для прямого открытия SPA-путей. В демо его предоставляет Vite. `hash` не требует
такого fallback. `memory` работает без `window`, `document` и UI-библиотек.
Это локальный адрес роутера; публичного стека Back/Forward в memory-режиме нет.

В `navigate()` и `resolve()` абсолютный путь `/users/42` относится к корню
приложения, без `base`. Относительные адреса разрешаются по правилам `new URL()`.
Полный browser URL того же origin, например `https://example.test/app/users/42`,
учитывает `base`; в hash-режиме полный URL содержит `#/users/42`.
При browser-режиме можно передать `window` явно, например из jsdom.
В одной browser-истории следует запускать один активный роутер.

При отказе после браузерного Back/Forward роутер восстанавливает прежнюю позицию
через `history.go()`. Адресная строка до завершения guard временно показывает цель
браузерного перехода. Служебная метка хранится в `history.state.__funcrouter`,
другие свойства объекта сохраняются. Если запись создана сторонним кодом и её
позиция неизвестна, восстановление заменяет её URL через `replaceState()`.
Прямые вызовы стороннего `pushState()` роутер не перехватывает.

## Отрисовка и ошибки

Обработчик маршрута синхронный. Возвращает функцию очистки либо `undefined`.
Асинхронные проверки выполняйте в guards. Фоновую работу внутри страницы
связывайте с `signal`, проверяя его перед изменением интерфейса.

```js
function page(context) {
  const app = mount(container, () => profile(context)); // FuncUI — только здесь
  return () => app.unmount();
}

// Тот же роутер без FuncUI:
function circle({ params }) {
  context.clearRect(0, 0, canvas.width, canvas.height);
  context.beginPath();
  context.arc(200, 200, params.radius, 0, Math.PI * 2);
  context.stroke();
}
```

После всех guards роутер подтверждает URL и маршрут, отменяет сигнал предыдущей
страницы, вызывает её cleanup и запускает новый обработчик. Ошибка parser или
guard сохраняет текущую страницу. Произвольные побочные эффекты обработчика
не откатываются: при его ошибке маршрут уже принят, подписки не уведомляются,
signal отменяется. Можно повторить тот же переход для новой попытки.

Опция `onError(error)` получает ошибки переходов, очистки и подписчиков.
Без неё используется `globalThis.reportError`, иначе `console.error`.
Программный `navigate()` также отклоняет Promise; события браузера сообщают
ошибку через `onError` и не создают необработанных Promise rejections.

## Разработка и примеры

Пакет экспортирует непосредственно `src/index.js`, без сборки библиотеки.
Из корня workspace:

```sh
npm install
npm run test:router
npm run dev:router     # FuncUI + FuncRouter
npm run dev:canvas     # HTML + JavaScript + Canvas 2D + FuncRouter
npm test              # все библиотеки и интеграционные тесты демо
npm run build         # все три демо
```

В `src/routes.js` находятся описание и сопоставление маршрутов, в `src/router.js`
порядок переходов и guards, в `src/history.js` browser/hash/memory-окружения и
перехват ссылок. Внутренние модули не входят в публичный API.
