# FuncUI + FuncRouter

**Reactive interfaces. Just JavaScript.**

Лёгкая UI-библиотека на JavaScript ES Modules: HTML-теги как функции, глубокая
реактивность через `$()` и обновления настоящего DOM. Без JSX, компилятора,
Virtual DOM и runtime-зависимостей.

Рядом находится **FuncRouter** — независимая библиотека маршрутизации на обычном
JavaScript. Она работает с FuncUI, другими UI-библиотеками и без UI-фреймворка.
Публичный API, guards, параметры и режимы истории описаны в [funcrouter/README.md](funcrouter/README.md).

```sh
npm run dev:router     # многостраничное SPA на FuncUI + FuncRouter
npm run dev:canvas     # vanilla JS + FuncRouter + Canvas 2D
npm run test:router    # тесты отдельного роутера
```

Новые приложения лежат в `demo-router/` и `demo-router-canvas/` и запускаются
независимо. `npm test` проверяет обе библиотеки и оба новых демо; `npm run build`
собирает все три приложения. Исходники FuncUI не зависят от роутера.

## Запуск

Нужны Node.js `^22.22.2`, `^24.15.0` или `>=26.0.0` и npm 7+.
В этой среде проект проверен на Node.js 26.3.0 и npm 11.16.0.

```sh
npm install
npm run dev
```

Vite напечатает локальный адрес, обычно `http://localhost:5173`.
Если порт занят, фактический адрес будет указан в терминале.

```sh
npm test         # node:test + jsdom: библиотеки и демо
npm run test:watch
npm run build   # production-сборки всех демо в их dist/
npm run preview # просмотр собранного демо
```

## Пакеты workspace

```text
funcui/               библиотека, публичный API и тесты
  src/index.js        ESM entry point
  test/               поведенческие тесты
demo/                 приложение, потребляющее библиотеку
  index.html          метаданные, #app и загрузка main.js
  src/main.js         композиция страницы через FuncUI
  src/components/     Hello, Counter, редактируемый список и JS-анимация
  src/styles.css      оформление и анимации
funcrouter/           отдельный роутер, публичный API и тесты
demo-router/          многостраничное SPA: FuncUI + FuncRouter
demo-router-canvas/   HTML и vanilla JS: FuncRouter + Canvas 2D
```

Корень использует npm workspaces. `demo` зависит от `funcui@0.0.0`; `npm install`
связывает локальные пакеты. Библиотека экспортирует непосредственно
`funcui/src/index.js`, поэтому Vite видит изменения её исходников без публикации,
копирования и промежуточной сборки.

CSS обновляется через Vite HMR. Изменения JavaScript автоматически перезагружают
страницу; сохранение состояния между изменениями исходников не предусмотрено.
При HMR entry point останавливает анимацию через `AbortController` и вызывает
`app.unmount()` для освобождения старого приложения.

## Первый интерфейс

```js
import { mount, $, div, h1, p, button } from 'funcui';

const state = $({ count: 0 });

const app = mount('#app', () => {
  div({ class: 'counter' }, () => {
    h1('Counter');
    p(() => state.count);
    button({ onClick: () => state.count++ }, 'Increment');
  });
});

// Когда приложение больше не нужно:
// app.unmount();
```

`$()` — обычная импортируемая функция. Свойства читаются и изменяются напрямую,
без `.value`, ручных подписок и повторного `mount()`.

## Публичный API

| Экспорт | Назначение |
| --- | --- |
| `$(object)` | Глубокий реактивный Proxy обычного объекта или массива |
| `reactive(object)` | Та же функция, что и `$` |
| `mount(selectorOrElement, callback)` | Монтирование и объект `{ unmount() }` |
| `For(readItems, renderItem, getKey)` | Реактивная коллекция с сохранением DOM по ключам |
| `insertHTML(markup)` | Вставка HTML-строки на месте вызова без дополнительного элемента |
| `div`, `p`, `button`, `input`, … | Функции стандартных HTML-тегов, возвращающие настоящие элементы |

Экспортируются теги для текста, структуры страницы, форм, таблиц и медиа.
Полный список находится в `funcui/src/elements.js`. Для тега `var`, имя которого
зарезервировано JavaScript, используйте `import { var as varTag } from 'funcui'`.
Внутренние effects, RenderScope и scheduler в публичный API не входят.

### HTML DSL

```js
div();
div('Hello');
div(123);
div({ class: 'container' });
div({ class: 'container' }, 'Hello');
div(() => 'Computed text');
div(() => {
  h1('Title');
  p('Description');
});
```

Первый необязательный аргумент — объект атрибутов. Содержимое может быть строкой,
числом, DOM-элементом, `null`, `undefined` или синхронным callback. Callback может
создавать вложенные теги и возвращать строку, число, элемент либо пустое значение.
Вторым аргументом или результатом callback может быть массив таких значений,
включая вложенные массивы: `div(() => items.map(item => p(item.name)))`.
Первый аргумент-массив и boolean-содержимое не поддерживаются; для условий
используйте обычный `if`. Элементы без закрывающего тега, например `input`,
не принимают содержимое.

Внутри callback HTML-функции автоматически добавляют элементы текущему родителю.
Снаружи они создают отсоединённые элементы. Возвращённый отсоединённый элемент
прикрепляется автоматически; уже имеющий родителя элемент повторно не вставляется
и не перемещается. Для динамической структуры создавайте элементы внутри callback,
а не возвращайте один и тот же ранее прикреплённый элемент на каждом обновлении.

Обычный текст создаётся через текстовые DOM-узлы, без `innerHTML`. Содержимое
`template` помещается в его стандартный `content`-фрагмент.

### Вставка готового HTML

`insertHTML()` принимает строку и добавляет разобранные DOM-узлы текущему
родителю. Соседние элементы сохраняются; дополнительная обёртка не создаётся.

```js
import { div, insertHTML, p } from 'funcui';

div(() => {
  p('Before');

  insertHTML(`
    <p>HTML with <strong>emphasis</strong>.</p>
    <p>Another paragraph.</p>
  `);

  p('After');
});
```

Функцию вызывают внутри `mount()` или render callback. Она возвращает `undefined`;
пустая строка ничего не добавляет. Атрибуты, callbacks и другие типы аргументов
не принимаются. Строка разбирается через браузерный `<template>`; его содержимое
переносится в текущую разметку.

**Автоматической очистки HTML нет. За источник строки и её предварительную
санитизацию отвечает разработчик.** HTML-атрибуты сохраняются по обычным правилам
браузера. Встроенные `<script>` не активируются вручную; это не делает произвольный
HTML безопасным. Выражения и обработчики FuncUI внутри строки не интерпретируются.
Обычный `p(markup)` по-прежнему выводит строку как текст.

`insertHTML()` использует реактивную границу окружающего callback:

```js
div(() => {
  insertHTML(state.markup);
});
```

Изменение `state.markup` пересоздаёт содержимое этого `div` по стандартным правилам
структурного рендера, с глобальным пакетированием синхронных записей. Собственного
реактивного блока функция не создаёт. Вставленные узлы удаляются вместе с содержимым
родителя или строкой `For()`; размонтирование также удаляет их.

### Два уровня обновления

```js
div(() => {
  h1('Profile');
  p(state.user.name);
});
```

Здесь `state.user.name` читается во внешнем callback. При изменении имени
содержимое этого `div` пересоздаётся. Так работают обычные `if`, `for` и другие
конструкции JavaScript, меняющие структуру интерфейса.

```js
p(() => state.user.name);
```

Здесь чтение принадлежит самостоятельному callback. При изменении имени
сохраняются `p`, его текстовый узел и соседи; обновляется только текст.

Первоначальный рендер выполняется синхронно. Записи через Proxy меняют данные
сразу, а последующие обновления DOM глобально группируются через `queueMicrotask()`.
Это работает по умолчанию во всех компонентах и независимых `mount()`:

```js
for (let index = 0; index < 1000; index++) state.count++;
// Один пересчёт подписанного effect с итоговым count.
```

Очередь использует `Set`: один effect выполняется не более одного раза за flush.
Новые effects включаются в текущий flush в порядке родитель → ребёнок.
Если уже выполненный effect снова инвалидирован, он попадает в следующую microtask.
Уничтоженные effects пропускаются, ошибка одного вычисления не блокирует остальные.

Чтение за пределами отслеживаемого callback не создаёт подписки. Например,
`const name = state.user.name` заранее получает обычное текущее значение.

### Состояние, условия и массивы

```js
const state = $({
  enabled: true,
  user: { name: 'Alex' },
  items: [{ name: 'One' }]
});

div(() => {
  if (!state.enabled) {
    p('Nothing to show');
    return;
  }
  for (const item of state.items) p(item.name);
});

state.items.push({ name: 'Two' });
state.items[0].name = 'Updated';
```

Вложенные объекты проксируются лениво и кэшируются. Поддерживаются циклические
ссылки, символьные ключи, `in`, перечисление свойств, добавление и удаление,
индексы и длина массивов, `push`, `pop`, `splice`, `sort`, `reverse` и другие
стандартные мутации. Условные зависимости пересобираются при каждом запуске.
Запись значения, равного предыдущему по `Object.is`, не запускает обновление.

### Реактивные коллекции с For

```js
import { $, For, ul, li, input, button } from 'funcui';

const state = $({ users: [{ id: 1, name: 'Ada' }, { id: 2, name: 'Sam' }] });

ul(() => {
  For(
    () => state.users,
    user => li(() => {
      input({
        value: () => user.name,
        onInput: event => user.name = event.target.value
      });
      button({ onClick: () => user.name += '!' }, 'Edit');
    }),
    user => user.id
  );
});

state.users.push({ id: 3, name: 'Maya' }); // создаётся только новая строка
state.users.reverse();                  // существующие строки перемещаются
state.users = state.users.map(user => ({ ...user })); // прежние ключи сохраняют DOM
```

`For()` вызывается внутри `mount()` или render callback, принимает три синхронные
функции и ничего не возвращает. Коллекция — массив обычных объектов, включая
объекты с null-прототипом; ключи — уникальные строки или числа. Пропущенный ключ,
дубликаты и неподдерживаемые элементы вызывают ошибку до изменения действующего
списка. Изменение ключа означает удаление прежней строки и создание новой.

Для каждого ключа создаётся свой владелец ресурсов и диапазон настоящих DOM-узлов.
Renderer может создавать несколько корней и обходиться без `return`. Добавление
и удаление затрагивает нужные диапазоны; перестановка использует наибольшую
возрастающую подпоследовательность, чтобы сократить перемещения сохранённых строк.
Удаление освобождает подписки, вложенные списки и обработчики строки.

`user` в renderer — стабильный Proxy-ссылка, **не идентичный** `state.users[index]`.
При замене объекта с тем же ключом ссылка и замкнутые на неё обработчики переходят
к новым данным. Подписки переносятся с прежнего объекта; одинаковые значения
свойств не вызывают обновлений DOM. Вложенные свойства также реактивны.
Чтение `user.name` в момент события получает актуальное значение; заранее
сохранённые `const name = user.name` и `const profile = user.profile` остаются
снимками значения/ссылки, как в обычном JavaScript. `Object.defineProperty()`,
замена прототипа и запрет расширения стабильной ссылки не поддерживаются.

Для точечного обновления используйте `li(() => user.name)` или вычисляемые
атрибуты. Прямое чтение внутри структурного callback, например
`li(() => { p(user.name); })`, по-прежнему пересоздаёт содержимое этого callback.
Обычные `for` и `.map()` работают как прежде; `For()` нужен для сохранения строк
динамической коллекции по ключам.

### Атрибуты, события и поля формы

```js
input({
  value: () => state.user.name,
  onInput: event => state.user.name = event.target.value
});

button({
  class: () => state.enabled ? 'active' : 'inactive',
  disabled: () => !state.enabled,
  title: () => `Items: ${state.items.length}`,
  'aria-pressed': () => state.enabled,
  onClick: () => state.items.push({ name: 'New' })
}, 'Add');

div({ style: 'color: red; font-weight: bold;' });
div({ style: { fontWeight: 600, opacity: () => state.enabled ? 1 : 0.5 } });
div({ style: () => state.enabled ? { color: 'green' } : { color: 'gray' } });
```

Поддерживаются `class` и `className`, `htmlFor`, boolean-атрибуты, `data-*`,
`aria-*`, строковый и объектный `style`, camelCase CSS-имена и CSS custom properties.
Числам в CSS автоматически не добавляется `px`: для размеров передавайте единицы.
`null` и `undefined` удаляют обычный атрибут. `false` удаляет обычный атрибут,
но сохраняется строкой `"false"` для `aria-*` и `data-*`.

Функции атрибутов — отдельные реактивные вычисления. `onClick`, `onInput`,
`onKeyDown` и другие `on…`-свойства являются обработчиками; они подключаются через
`addEventListener`, выполняются только при событии и не собирают зависимости.
Имя события получается приведением части после `on` к нижнему регистру:
для `dblclick` используйте `onDblClick`. Опции listeners на этом этапе отсутствуют.

`value`, `checked`, `selected`, `readOnly`, `selectedIndex` и `indeterminate`
работают через подходящие DOM-свойства. Неизменившееся `value` повторно не
присваивается полю, чтобы сохранять позицию курсора. Контролируемый `select`
восстанавливает значение после пересоздания списка `option`.

### Компоненты и жизненный цикл

Компонент — обычная функция, принимающая параметры и вызывающая HTML-функции.
Каждый вызов может иметь собственное состояние. Рабочие примеры с комментариями
находятся в `demo/src/components/`.

Компонент можно собрать из нескольких функций в одном файле. Экспортировать
нужно только ту функцию, которой пользуется приложение:

```js
import { article, h2, p } from 'funcui';

export function hello({ name }) {
  article(() => {
    heading(name);
    description();
  });
}

function heading(name) {
  h2(`Hello, ${name}!`);
}

function description() {
  p('A component made of ordinary functions.');
}
```

При вызове внутри `mount()` или callback HTML-функции `return` у компонента
необязателен: элементы добавляются в текущий RenderScope автоматически.
Компонент может создать и несколько корневых элементов. Если нужен сам
DOM-элемент как результат вызова, можно написать `return article(...)` —
этот вариант тоже поддерживается, без повторной вставки элемента.

Это отличается от вычисления текста: `p(() => state.count)` возвращает значение
автоматически, а в блочной форме нужен `p(() => { return state.count; })`.
Запись `p(() => { state.count; })` возвращает `undefined`, как и любая такая
функция JavaScript.

В демо экспортируемые `hello()` и `counter()` не используют `return`.
Приветствие, поле имени, список возможностей, значение счётчика и кнопки
создаются небольшими локальными функциями в соответствующих файлах компонентов.

`mount()` очищает контейнер и создаёт корневой RenderScope. `unmount()` удаляет
DOM, рекурсивно освобождает подписки и обработчики событий. Повторный вызов
безопасен. Повторный `mount()` в тот же контейнер сначала размонтирует предыдущий.
Отсоединённое дерево FuncUI, возвращённое в callback, переходит под управление
жизненного цикла приложения. Для реактивных деревьев используйте `mount()` и
`unmount()`, а не ручное удаление DOM-узлов.

## Внутреннее устройство

| Модуль | Ответственность |
| --- | --- |
| `reactivity.js` | Proxy, кэши исходных объектов, операции и массивы |
| `effect.js` | Граф `WeakMap<Target, Map<PropertyKey, Set<Effect>>>`, контекст и владельцы ресурсов |
| `scheduler.js` | Microtask-очередь, дедупликация, порядок родитель → ребёнок, ограничение циклов |
| `scope.js` | Контекст DOM, вычисление содержимого, точечный текст и структурный рендер |
| `for.js` | Проверка ключей, подготовка/очистка строк и минимизация перестановок |
| `item-reference.js` | Стабильная ссылка строки и перенос зависимостей на заменённый объект |
| `range.js` | Диапазон DOM-узлов, перемещение и удаление строки |
| `attributes.js` | DOM-атрибуты и свойства, стили, события |
| `elements.js` | Фабрика и экспорты HTML-тегов |
| `insert-html.js` | Разбор HTML-строки и вставка узлов в текущий render callback |
| `mount.js` | Контейнеры и жизненный цикл корневых деревьев |

Каждый scope и элемент имеет владельца ресурсов. Структурный callback сначала
строит следующее дерево в отсоединённом `DocumentFragment`. После успешного
вычисления предыдущая генерация освобождается и заменяется новой. При исключении
неполная генерация очищается, а последний успешный DOM сохраняется. Это не DOM
diffing и не Virtual DOM: фрагмент содержит настоящие DOM-узлы.

Контексты effect, владельца и DOM-родителя восстанавливаются через `try/finally`.
Перед пересчётом effect удаляет старые зависимости, а затем собирает фактически
прочитанные. Пустые записи подписок тоже удаляются. Отложенное обновление
уничтоженного effect пропускается.

## Ошибки и ограничения Stage 1

- Ошибка первоначального рендера передаётся вызывающему коду; созданные ресурсы
  освобождаются. Ошибка отложенного обновления передаётся `globalThis.reportError`,
  если он доступен, иначе — `console.error`. Остальные effects продолжают работу.
  Зависимости неудачного вычисления соответствуют чтениям до исключения;
  изменение прочитанного условия может запустить следующую попытку.
- Render callbacks и вычисления атрибутов синхронны. `async`-функции и возврат
  Promise не поддерживаются. Обработчики событий могут быть асинхронными:
  ошибки таких обработчиков обрабатывает приложение.
- После 100 запусков одного effect в непрерывном каскаде microtasks scheduler
  останавливает этот effect и сообщает о цикле. Render callbacks следует оставлять без мутаций
  собственного состояния.
- `$()` принимает обычные объекты, объекты с null-прототипом и массивы.
  Примитивы, `Date`, `Map`, `Set`, DOM-объекты и экземпляры классов как корневой
  аргумент отклоняются. Вложенные специальные объекты сохраняются без Proxy;
  их замена реактивна, внутренние мутации — нет.
- Изменять состояние нужно через Proxy. Запись в исходный объект в обход Proxy,
  изменение прототипа и `Object.defineProperty()` не отслеживаются.
  Объектное значение неизменяемого неконфигурируемого свойства возвращается
  как есть, чтобы соблюдать инварианты JavaScript Proxy.
- Пересоздание структурного scope может сбрасывать фокус и локальное состояние
  его дочерних DOM-узлов. Для редактируемых полей используйте точечные bindings.
- SVG, MathML, custom-element factory, SSR, hydration, DI и общий DOM
  diffing в Stage 1 не реализованы. Сохранение по ключам доступно явно через `For()`.
  Маршрутизация предоставляется отдельным пакетом FuncRouter.

## Проверки

`npm test` проверяет HTML DSL, вложенность, все виды содержимого, глубокую
реактивность, массивы, условия, изоляцию effects, динамические зависимости,
атрибуты и стили, поля формы, глобальное пакетирование, очистку, исключения и защиту
от циклов. Тесты `For()` проверяют идентичность узлов, число изменений DOM,
добавление/удаление, минимальные перестановки, замену объектов, вложенные списки,
очистку подписок и восстановление после ошибок.

Тесты `insertHTML()` проверяют порядок узлов и отсутствие обёртки, HTML-сущности,
таблицы и `template`, сохранение атрибутов без очистки, структурные обновления,
строки `For()`, размонтирование и сохранение рабочего DOM при ошибках.

В демо четыре карточки: Hello, Counter, редактируемый список и JS-пружина.
Список позволяет добавлять, редактировать, удалять и перемещать пользователей,
заменять объекты с прежними ID и менять все имена обычным циклом. Пружина считает
силу, скорость и положение через `requestAnimationFrame`, поддерживает настройку
жёсткости и затухания, смену цели, паузу и сброс. DOM обновляется через FuncUI;
отдельный `AbortSignal` отменяет кадры при завершении жизни демо.
Интеграционные тесты проверяют эти действия, включая остановку кадров.

На узких экранах карточки переходят в одну колонку. `prefers-reduced-motion`
отключает декоративные анимации и transitions; физический пример запускается
только по нажатию пользователя.
